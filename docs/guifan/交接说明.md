# 交接说明

## 项目交接原则

本项目采用文件驱动接力开发，不依赖对话上下文，所有规则、分工、历史经验以项目内文档为准。账号之间相互隔离，AI 之间无法自动互通消息。交接唯一载体为整套项目文件夹。

## 对话交接纪律（换账号/接力开发强制）

1. **唯一对话记录文件**：全项目对话交接统一写入 `docs/jiaojie/00-对话交接总账.md`；
   每轮对话/里程碑完成，把关键决策、改动、进度、待办追加到该文件（最新状态区 + 交接历史区），
   禁止只口述不记录、禁止各自另建记录文件。
2. **新账号上线流程**：先读总账「〇、接手者速查」→「一、最新状态」→
   docs/jingyan-zichan/14-jingyan-liushui.md → docs/jingyan-zichan/代码资产库.md/指令模板库.md → AGENTS.md，再读源码；未走完此序不得动手。
3. **文件保存边界**：所有对话产生的记录、交付物、任务卡、经验、脚本**只允许保存到本项目文件夹内**
   （`C:\Users\29236\Desktop\桌面小程序开发\`），禁止保存到桌面其他位置；交接唯一载体 = 整套项目文件夹。
4. **元文件唯一来源**：AGENTS.md 为全项目长期约束唯一来源，新增强制纪律追加至 AGENTS.md 并记录变更日志。

## 开发基础约束



1. 严格遵守模块分工：data\_store.py、pages\_home.py、pages\_grow.py、pages\_record.py、pages\_tool.py 各司其职，非指定需求禁止跨模块改动；

2. 只执行用户明确指定的单点改动，禁止自动重构、额外美化优化、新增无关功能；

3. 布局修改只调整指定外层容器外边距，内部 padding、组件、逻辑、样式保持原样；

4. 修改后只输出改动片段并且标注改动行，不重写整个 py 文件；

5. 遇到大规模重构、多模块联动类复杂改动，必须先拆解成多个小步骤，每步与用户确认后再继续，禁止一次性大范围乱改。

## 项目自我增值铁律



1. **开工前**：查阅 docs/jingyan-zichan/14-jingyan-liushui.md 经验流水账、docs/jingyan-zichan/代码资产库.md、docs/jingyan-zichan/指令模板库.md，优先复用成熟方案与现成轮子，规避历史踩坑，禁止重复造轮子；

2. **执行中**：识别新产生的易错陷阱、稳定可复用的代码方案；

3. **收尾时**：新踩坑追加进经验流水账，可用轮子与验证过的指令归档至对应资产库，对照验收清单自检；

4. 遇到用户口头说明的偏好、特殊约束、临时规定，主动向用户确认后，一并写入经验流水账，避免下次丢失；

5. 每次迭代沉淀资产，持续增值；项目阶段收尾时，主动清理合并过时、失效、冗余的旧资产，保持资产库精简有效。

本条为预埋规则，暂不启动交接，后续接力时直接生效。
