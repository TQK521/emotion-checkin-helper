# 4 · 项目结构规范

> 每个新项目按此结构搭建，目录名和文件名统一，方便 AI 接手维护、也方便用户看懂。
> 本项目已按 webapp 主线对齐标准工程布局（webapp/docs/scripts/test/archive），根目录只放元文件与用户数据。

## 一、标准目录结构（webapp 主线）

```
桌面小程序开发/
├── AGENTS.md                # 项目宪法：全部强制约束唯一来源
├── README.md                # 项目总览（webapp 主线：启动/结构/数据红线/红色警告）
├── CHANGELOG.md             # 版本简表
├── CONTRIBUTING.md          # 贡献指南
├── LICENSE / SECURITY.md / .gitignore
├── checkin_data.json        # 旧版用户数据（数据红线，绝不入库）
├── webapp/                  # 当前主线源码工程
│   ├── src/
│   │   ├── app/             # 装配层：main.ts / App.vue / router / providers / components
│   │   ├── core/            # 领域契约（domain）/ 统计（stats）/ 状态（store）
│   │   ├── features/        # 四功能域：home / record / tool / manual（测试 co-located）
│   │   ├── services/        # 存储端口 + tauri/browser/memory 三适配器 + importer
│   │   ├── shared/          # 公共 UI / lib / styles（tokens.css 主题变量）
│   │   └── assets/data/     # 静态软件数据（chapters/toolkit/emotions）
│   └── src-tauri/           # Rust 壳：lib.rs 四命令 + capabilities + tauri.conf.json
├── docs/                    # 文档体系（见下方「文档命名与归档规范」）
├── scripts/                 # 转换/工具脚本（如 export_webapp_data.py）
├── test/accept/             # 验收与实验脚本（_exp_*.py，复用 accept_lib）
└── archive/                 # 历史数据快照（淘汰物归档区）
```

## 二、分层职责（src 六层，维护的关键）

| 层 | 目录 | 职责 | 注意 |
| --- | --- | --- | --- |
| 装配层 | `src/app/` | 应用组装：main.ts 装配存储适配器、路由、根组件 | 跨域依赖的组件必须放 app/components（boundaries 红线） |
| 领域层 | `src/core/` | 数据契约、统计纯函数、Pinia store | 零 UI 依赖，可独立测试 |
| 功能域 | `src/features/` | 四页面各自视图与交互（home/record/tool/manual） | 域内高内聚，测试 co-located |
| 服务层 | `src/services/` | 存储端口（storage.port）+ 三适配器 + 导入迁移 | 适配器按运行态切换（tauri/browser/memory） |
| 共享层 | `src/shared/` | 公共 UI 组件、工具函数、全局样式 | **只许依赖 shared**，组件依赖 core/services 必须上移到 app 层 |
| Rust 壳 | `src-tauri/` | 数据命令（原子写/备份/导入）+ 窗口配置 | 核心数据安全层自研自控 |

## 三、命名约定

- **源码文件**：组件 `PascalCase.vue`；工具/模块 `kebab-case.ts`；类型/接口 `PascalCase`；
- **变量/函数**：`camelCase`；常量 `SCREAMING_SNAKE_CASE`；
- **目录**：小写短名（`app/core/features/services/shared`）；
- **功能相关文件放对应模块目录**，禁止把所有代码堆在一个文件里（如 app 层不塞业务逻辑）。

## 四、配置约定

- 前端构建/依赖：`vite.config.ts`、`package.json`、`pnpm-workspace.yaml`；
- 桌面配置：`src-tauri/tauri.conf.json`（窗口/打包/capabilities）；
- 代码内禁止硬编码路径与可调参数；需要改时改配置文件。

## 五、文档命名与归档规范（2026-11-02 立，全项目强制）

1. **编码**：所有文档一律 UTF-8 无 BOM（Excel/记事本打开不乱码，程序解析不污染首字段）；
2. **目录命名**：拼音短名（`guifan` 规范 / `jiaojie` 交接 / `jingyan-zichan` 经验资产 / `moban` 模板 / `xiang mu quan jing` 用户自存）；禁止中文长目录、禁止散落根目录；
3. **文件命名**：
   - 规范/导航类：`编号-中文短名.md`（如 `00a-执行检查卡.md`、`3-技术选型指南.md`）；
   - 复盘/记录类：`YYYY-MM-DD-中文简述.md`（如 `2026-11-01-绿色版双路径崩溃复盘.md`）；
   - 资产库类：`编号-拼音或中文短名.md`（如 `14-jingyan-liushui.md`、`代码资产库.md`）；同一类内命名必须一致；
4. **结构模板**：每类文档固定模板——
   - 规范类：`# 标题` → `> 用途/权威源引用块` → `## 正文分节` → 表格优先；
   - 复盘类：一句话结论 → 现象/根因/影响/方案/预防/提炼去向（AGENTS.md 核心约束一）；
   - 资产库类：`# 标题` → `> 用途与维护规则` → 索引表 + 明细表；
5. **存放位置**：新文档必须进 `docs/` 对应子目录（规范→guifan、交接→jiaojie、资产→jingyan-zichan、模板→moban），禁止散落根目录（核心约束十四）；
6. **语言**：正文中文为主，代码、API、技术名词保留英文（不强制全英文，读者能读懂即标准）。

## 六、根目录守则

- 根目录只放 **7 个元文件**（AGENTS.md / README.md / CHANGELOG.md / CONTRIBUTING.md / LICENSE / SECURITY.md / .gitignore）与用户数据 `checkin_data.json`；
- 新增散文件一律归位或删除（核心约束十四第 2 条）。
