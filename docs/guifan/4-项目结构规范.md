# 4 · 项目结构规范

> 每个新项目按此结构搭建，目录名和文件名统一，方便 AI 接手维护、也方便用户看懂。

## 标准目录结构

```
项目名/
├── main.py               # 程序入口（启动界面）
├── config.json           # 配置文件（参数、路径、用户偏好）
├── requirements.txt      # 依赖清单
├── README.md             # 项目说明（给开发/维护的人看）
├── 使用说明.md            # 给最终用户看（交付时随包）
├── 环境配置说明.md        # 需要环境时才有（非专业人员可操作）
├── ui/                   # 界面层：窗口、控件、页面
│   └── main_window.py
├── core/                 # 业务逻辑层：核心功能、计算、处理
│   └── service.py
├── data/                 # 数据层：程序产生的数据文件（运行后自动生成）
├── logs/                 # 日志目录（运行后自动生成）
├── utils/                # 工具函数：路径、时间、格式化
└── tests/                # 测试代码
    └── test_core.py
```

## 分层职责（三层分离，维护的关键）

| 层 | 目录 | 职责 | 注意 |
| --- | --- | --- | --- |
| 界面层 | `ui/` | 显示窗口、接收点击、展示结果 | **不含业务逻辑**，改动界面不影响功能 |
| 业务层 | `core/` | 核心功能、计算、数据处理 | **不含界面代码**，可独立测试 |
| 数据层 | `data/` + `config.json` | 保存/读取数据与配置 | 用户可备份、可迁移 |

## 命名约定

- 文件名：全小写 + 下划线（`main_window.py`、`config.json`）。
- 类名：大驼峰（`MainWindow`、`UserService`）。
- 函数/变量：小驼峰或下划线（`save_config()`、`user_name`）。
- 功能相关的文件放对应模块目录，禁止把所有代码堆在一个文件里。

## 配置约定

- `config.json` 统一管理：窗口大小、默认路径、选项参数、版本号。
- 代码内禁止硬编码路径和可调参数；需要改时改配置文件即可。
