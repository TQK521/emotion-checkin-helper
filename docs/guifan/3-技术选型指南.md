## 一、当前主线方案（默认，不可随意更换）

| 层 | 选型 | 版本/说明 |
| --- | --- | --- |
| 前端框架 | Vue 3（组合式 API） | 3.5.x，`webapp/package.json` 锁定 |
| 语言 | TypeScript | 严格模式，全量类型检查（vue-tsc） |
| 构建 | Vite | 8.x，开发热更新 + 产物构建 |

| 包管理 | pnpm | >=12，`pnpm-workspace.yaml` 管控构建审批 |
| 代码质量 | ESLint + vue-tsc | boundaries 分层依赖检查 + 类型检查 |

## 二、为什么是这个选型（2026-11-01 重构决策）

1. **体积与性能**：Tauri 产物为单 exe（约 4.7MB），远小于 Electron（>100MB）；WebView2 系统自带，运行期零第三方运行时依赖；
2. **数据安全自控**：核心数据读写走 Rust 命令（原子写 + 损坏隔离 + 7 份备份），数据层完全自研自控（核心约束十六）；
3. **前端生态成熟**：Vue3 + TS + Vite 组件化开发效率高，质量门（typecheck/lint/test/build）可自动化；
4. **路径敏感已实证**：WebView2 对 exe 所在路径**双敏感**（中文路径 → 拒绝访问崩溃；桌面目录 → 资源占用崩溃），绿色版必须放纯英文非桌面目录（见 `docs/jingyan-zichan/10-shigu-fupan/2026-11-01-绿色版双路径崩溃复盘.md`）。

## 三、备选方案（仅特殊需求时评估，须向用户说明理由）

| 方案 | 优势 | 代价 | 适用场景 |
| --- | --- | --- | --- |
| Electron | 生态最大、跨平台最稳 | 包极大（>100MB）、内存高 | 需要 Node 原生生态深度集成 |
| React + Tauri | 组件生态大 | 与现状 Vue 栈不兼容，迁移成本高 | 团队 React 背景 |
| Rust 原生 GUI（egui/slint） | 极致性能、无 WebView | 开发效率低、UI 生态弱 | 高性能图形场景 |

## 四、选择决策树

```
新功能/新项目是什么类型？
├─ 桌面小工具、数据本地优先、要绿色版 exe → 本栈（Vue3+TS+Tauri2），默认
├─ 需要复杂图表/画布交互            → 本栈 + 前端图表库（ECharts 等）
├─ 需要 Node 原生能力深度集成        → 评估 Electron（体积换能力）
├─ 纯 Web 页面（无桌面壳）           → 去掉 Tauri，Vite 产物直接部署
└─ 其他特殊需求                      → 说明理由后另行选型
```

## 五、数据存储方案

| 运行态 | 存储位置 | 说明 |
| --- | --- | --- |
| 桌面正式态（Tauri） | `%APPDATA%\com.tqk.emotioncheckin\checkin_data.json` | Rust 命令原子写；当日自动备份；损坏改名保留现场；保留最近 7 份备份 |
| 浏览器开发态 | localStorage（key=`checkin-dev-db`） | 仅开发调试，不碰正式数据 |
| 测试态 | InMemory 适配器注入 | 单元测试零污染 |
| 旧版数据（根目录） | `checkin_data.json` | **数据红线**：只读迁移，禁止污染 |

## 六、依赖管理

- 前端依赖：`pnpm-lock.yaml` 锁定（pnpm >=12）；新增依赖须过 `pnpm-workspace.yaml` 的 allowBuilds 审批；
- Rust 依赖：`Cargo.lock` 锁定；cargo 拉取走系统代理时用 `NO_PROXY` 压制（见经验流水账 2026-11-01 段）；
- 所有命令与质量门见 `webapp/README.md`。
