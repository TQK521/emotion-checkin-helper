# 6 · 测试规范

> 交付前必须完成测试；测试不通过不交付。webapp 主线：质量门四件套 + 验收分层自检。

## 一、质量门四件套（每轮改动必跑，见 `webapp/README.md`）

| 命令 | 作用 | 失败即 |
| --- | --- | --- |
| `pnpm typecheck` | vue-tsc 全量类型检查 | 类型错误 → 不交付 |
| `pnpm lint` | ESLint（含 boundaries 分层依赖检查） | 边界/规范错 → 不交付 |
| `pnpm test` | Vitest co-located 单元测试（89+ 用例） | 断言失败 → 不交付 |
| `pnpm build` | vue-tsc + vite build 产物构建 | 构建失败 → 不交付 |

> PowerShell 下命令输出可能被吞，`pnpm test *> 日志.txt` 落盘后查看。

## 二、测试分层

### 1. 单元测试（Vitest，co-located）
- 每个核心纯函数至少测一遍：正常输入、边界输入、非法输入；
- 覆盖重点：`src/core/stats`（统计口径）、`src/core/domain`（数据契约）、`src/services`（适配器/迁移）、各 feature 的逻辑；
- 数据注入 InMemory 适配器，**零污染真实数据**。

### 2. 组件/视图测试
- 四功能域（home/record/tool/manual）测试与组件同目录（co-located）；
- 交互路径覆盖：路由切换、状态流转、触底加载、删除确认、空态。

### 3. 验收脚本（GUI/端到端，复用资产）
- 复用 `docs/jingyan-zichan/11-yanshou-kufu/accept_lib.py` + 模板 `test/accept/_exp_TEMPLATE_accept.py`（两段式+段门+`--fast`）；
- **分层自检三段**：段1 纯逻辑（零 GUI）→ 段2 GUI 冒烟 → 段3 全量断言；冒烟 FAIL 即停只修脚本；
- 断言纪律：断言必须能真实失败；先 DIAG 再断言；弹窗/wait_window 路径禁入脚本；
- **数据隔离三件套**：临时数据源 + 操作前后真实数据哈希核验 + 验收前确认基线哈希；
- 截图留证（`_exp_shot_*.png`）入 `test/accept/`。

### 4. 异常场景测试（最容易漏，必须测）

| 场景 | 预期表现 |
| --- | --- |
| 空输入 / 未填写就点确定 | 友好提示，不崩溃 |
| 数据文件不存在 / 损坏 | 自动重建空数据或损坏改名保留现场，不崩溃 |
| 导入非法/旧格式数据 | importer 校验契约，拒绝或安全迁移，不写坏正式数据 |
| 重复快速点击按钮 | 不卡死、不重复处理 |
| 中文路径 / WebView2 敏感路径 | 绿色版放纯英文非桌面目录（交付红线） |
| 断网（如无联网功能则跳过） | 本地应用无联网依赖 |
