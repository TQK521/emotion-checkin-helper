# 1 · 开发流程（阶段零 + 六阶段）

> 任何桌面小程序都按这七步走。每步有明确产出物，做完一步再进下一步。

## 流程图

```
开工前预估 → 需求分析 → 方案设计 → 编码实现 → 测试 → 打包发布 → 运行维护（→ 回到需求分析，迭代）
```

## 阶段零：开工前预估（强制，先于一切步骤）

> 任何**深度分析、重构、批量修改**类需求，动手前必须先完成本阶段，经确认后才进入阶段一，避免不必要的工作与返工。

- **先预估交付时间**：按模块拆解工作量，逐项给出预估时长与总时长（含验证与交付环节），并说明关键耗时点。
- **给出修改建议**：指出需求中可精简、可延后、有风险或存在更优做法的地方，把取舍点与选择权交给用户，不擅自扩范围。
- **等确认再动手**：时间预估与修改建议得到用户确认后，才开始正式分析或编码；用户未确认前，不进入任何实质实现。
- 📦 产出：预估与建议说明（时间表 + 取舍点清单）

## 各阶段要点与产出

### 阶段一：需求分析
- 明确：核心功能、目标用户、使用场景。
- 用一句话说清"这个程序帮谁解决什么问题"。
- 区分：**必须做**（核心） / **以后再做**（扩展），防止需求蔓延。
- 📦 产出：需求确认单（功能清单 + 边界说明）

### 阶段二：方案设计
- 技术选型：语言 + GUI 框架（见《3-技术选型指南.md》）。
- 架构分层：界面层 / 业务逻辑层 / 数据层 分离。
- 规划：模块划分、数据存储方式、配置文件、界面草图。
- 📦 产出：方案说明（目录结构 + 模块划分 + 存储设计）

### 阶段三：编码实现
- 按模块小步实现，先跑通主流程，再补细节。
- 遵守编码规范（见《5-编码与可维护性规范.md》）。
- 每完成一个功能点，做一次小结/记录。
- 📦 产出：可运行版本 + 修改记录

### 阶段四：测试
- 核心逻辑：单元测试；全部功能：手工走查。
- 重点测异常：空输入、文件不存在、路径含中文、重复点击、异常退出。
- 📦 产出：测试记录、缺陷修复清单

### 阶段五：打包发布
- 打包为免安装可执行程序（见《7-打包交付规范.md》）。
- 随包附带《使用说明》和（如需）《环境配置说明》。
- 📦 产出：`软件名_v版本号.zip`，可一键转发

### 阶段六：运行维护
- 收集用户反馈 → 新需求 → **回到阶段一**，迭代升级。
- 靠日志定位问题；版本号递增；文档随代码更新。
- 📦 产出：新版本发布 + 更新说明

## 贯穿全程的维护习惯（让程序"能改得动"）

1. 目录按功能分模块，命名一眼看懂。
2. 配置放独立文件（JSON/ini），不写死在代码里。
3. 函数/类单一职责，避免"大而全"的巨函数。
4. 关键逻辑写注释，接口写说明。
5. 程序内置日志：记录关键操作 + 错误堆栈。
6. 改动有记录（文档"修改记录"表），可回溯、可回滚。
7. 测试用例保留，每次改动后回归一遍。
8. 版本号语义化，发布记录留存。
