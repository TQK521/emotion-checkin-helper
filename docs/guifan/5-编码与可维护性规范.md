# 5 · 编码与可维护性规范

> 目标：三个月后的 AI 和用户自己，都能快速看懂、安全改动这个程序（webapp 主线）。

## 一、命名与风格

- 统一命名规则（见《4-项目结构规范.md》第三节）；
- 中英文注释均可，但**关键逻辑必须写注释**：这段代码在做什么、为什么这么做；
- 每个模块/组件/重要函数顶部写说明（docstring/注释），一句话讲清用途和入参出参；
- TypeScript 全量严格类型：**禁止 `any` 逃逸**；领域契约集中在 `src/core/domain`，页面不得自造数据形状。

## 二、模块化与单一职责（src 六层红线）

- 一个函数只做一件事；一个功能域只装自己的页面；
- **layered 边界（ESLint boundaries 强制）**：
  - `shared` 层**只许依赖 shared**；组件若依赖 core/services 必须放 `src/app/components/`，放 shared/ui 会报 `no-ignored-dependencies`；
  - 判断法：数 import 里有没有 core/services/features 的路径；
  - 装配只在 `app` 层做（main.ts 装配存储适配器 + 路由 + load）；
- 避免重复代码：相同逻辑抽成公共函数（`src/shared/lib`）。

## 三、配置与数据

- 所有可调参数进配置文件（`vite.config.ts` / `src-tauri/tauri.conf.json`），**禁止硬编码路径和魔法参数**；
- 用户数据统一由 `src/services` 存储适配器读写，业务层不直接碰文件系统；
- 运行态切换：正式数据走 Tauri Rust 命令，开发态走 localStorage（key=`checkin-dev-db`），测试注入 InMemory 适配器——**任何路径都不写真实正式数据**。

## 四、错误处理（数据安全是命根子）

- 数据层（Rust 命令）必须**原子写**（临时文件 + rename 替换），崩溃不损坏原数据；
- 数据损坏：改名保留现场（`checkin_data_损坏_<ts>.json`），不静默覆盖；
- 备份：当日自动备份 + 保留最近 7 份（`checkin_data_备份_<日期>.json`）；
- 前端错误处理：所有可能失败的操作（读取、解析、导入）都要兜底，给用户友好提示（中文、可操作），不给英文报错堆栈；
- 空输入、文件不存在、路径含中文/空格、重复点击，都必须有兜底。

## 五、日志

- Rust 侧：关键数据操作打日志（谁在什么时候做了什么）；出错记完整错误信息；
- 前端：开发态 console 分组打印；线上态可关；
- 排查走「先对照后排除」（复制到已知成功环境二分定位），取证以日志/哈希落盘为主，截图仅用于用户视角确认。

## 六、版本与记录

- 每次交付同步更新：`CHANGELOG.md`（简表）+ `docs/jiaojie/00-对话交接总账.md`（详细）；
- 版本号：修复小问题 +0.0.1；加小功能 +0.1；大改版 +1；
- Git 纪律（核心约束十五）：本地每次必 commit；每累计 5 次 commit 才 push 一次；release 打包等用户明确指令。

## 七、安全底线（AI 必守）

- 不收集、不上传任何用户数据；所有数据本地保存（`%APPDATA%\com.tqk.emotioncheckin\`）；
- 不写破坏性代码；清理类操作先备份再提示；
- 生成的代码避免常见漏洞：路径拼接要安全（Rust 用 `FilePath` 类型而非裸字符串拼接）、外部输入要校验（导入迁移先校验契约再写回）；
- 根目录 `checkin_data.json` 是**数据红线**：绝不入库、不删除、不覆盖、不被测试污染。
